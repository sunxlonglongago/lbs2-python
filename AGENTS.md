# Agent notes for this repository

## Project

Python port of LBS^2: the original ASP + Access weblog rewritten on Flask +
SQLite, with the frontend taken over verbatim from the static HTML/CSS/JS that
the ASP pages emitted.

## Stack

- Backend: Python 3.10, Flask, stdlib `sqlite3` (no ORM), uv, systemd + nginx.
- Frontend: plain HTML/CSS/JS, keeping the original three themes plus
  `common.js` and `messageform.js` untouched.
- Conventions: Flask + stdlib sqlite3 + uv + Makefile + systemd, following an
  already proven Flask project skeleton.

## Layout

- `docs/database.md`, `docs/api.md`, `docs/openapi.json` — data dictionary,
  API reference, OpenAPI description (all generated by `make docs`).
- `frontend/` — static frontend sources.
- `server/src/` — backend sources; this is the production directory.
- `server/src/tools/` — database initialisation, schema check and docs export.
- `server/src/static/` — frontend output, committed on purpose.
- `dev-data/` — local development data, git-ignored.

## Commands

- `make dev` — run locally (initialises `dev-data/` on first start).
- `make fe` — sync the frontend into `server/src/static/`.
- `make db-init` / `make db-check` — create and verify a database (they act on
  `dev-data/`, or on `DATA_DIR=` when given on the command line).
- `make docs` — regenerate the data dictionary, API reference and OpenAPI spec.
- `make install` / `make update` / `make service-install` — deployment.
- `make test_api_full` — the full business API end-to-end suite.

## Checks

- Backend syntax: `python3 -m py_compile server/src/*.py server/src/tools/*.py`
- Schema drift: `make db-check` (must print `schema matches the code`)
- Full API suite: `make test_api_full` (must end with `all green`)

## Rules

- `server/src/schema.py` is the single source of truth for the database layout:
  the DDL, the declared field types the docs and `tools/check_db.py` read, and
  the built-in user groups. Change it there, then run `make db-check` and
  `make docs`. Table and column names must not be renamed.
- When a business API changes, update `docs/api.md`, `docs/openapi.json` and the
  scenarios under `server/tests/api_e2e/` in the same change.
- Keep the original DOM structure (ids and classes) in the frontend, otherwise
  the three bundled themes stop working.
- Every public URL keeps the ASP look: pages as `default.asp` / `article.asp?...`,
  API as `/api/xxx.asp`. `app.AspPathMiddleware` strips the trailing `.asp`
  before routing; the files themselves stay `.html`, and `.html` URLs all 302 to
  their `.asp` form (the upload page a message form embeds is `upload.asp`).
  New pages must be registered in `LEGACY_PAGES` and `PAGE_REDIRECTS`; new API
  routes need no extra work.
