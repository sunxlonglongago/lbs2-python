# LBS^2 (Python port)

A Python port of LBS^2 v2.0.304, the 2005 ASP + JScript + ADODB + Access weblog
engine: Flask + SQLite backend, static frontend ported from the original pages.

- `server/src/` — Flask application, data layer, import and seed tooling.
- `server/src/static/` — built frontend output, generated by `make fe` and committed.
- `frontend/` — static frontend sources (the original CSS/JS plus page skeletons).
- `docs/` — data dictionary, API reference, OpenAPI spec and the porting plan.

## URL layout

Public paths look exactly like the ASP original: pages are `default.asp`,
`article.asp?id=1`, `admin.asp`, and the API is `/api/articles.asp`,
`/api/articles/1/comments.asp` and so on. A WSGI middleware strips the trailing
`.asp` before routing, so the files on disk are still `frontend/*.html`; every
`.html` URL answers with a 302 to its `.asp` form (including the upload page that
the message forms embed, which is served as `upload.asp`).

## Running locally

```bash
make server_dev
```

This imports the original Access data into `dev-data/`, writes the hello world
demo rows and starts Flask on `http://127.0.0.1:5059`. Default login:
`Admin / comeon`.

The data steps can also be run on their own:

```bash
make db-import   # import the original data/*.mdb (blog.mdb, gbook.mdb)
make db-seed     # write the demo rows
make db-schema   # verify the schema against the Access reference
```

Point `LBS_SOURCE_DATA` at your own copy of the original `data/` directory (the
one holding `blog.mdb` and `gbook.mdb`), or pass the files directly:

```bash
make db-import LBS_SOURCE_DATA=/path/to/lbs/data
```

You do not need the original database to run the site: `make db-seed` creates the
schema and fills in the demo rows.

## Build and deploy

```bash
make build       # copy frontend/ into server/src/static/
make install     # install into /data/release/lbs
make service-install
```

Runtime state (the SQLite database, `secret_key`, backups) lives in
`RELEASE_DIR/data`.

## Database

Table and column names match the original Access database exactly
(`blog_Article`, `blog_Comment`, `blog_Settings`, `blog_User`, `Guestbook`, …).
The column-by-column comparison against the Access original, the type mapping
and the index list are all in `docs/database.md`.
