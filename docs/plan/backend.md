# Backend design

Stack and conventions: Flask + stdlib sqlite3 + uv + Makefile + systemd. Only the
business domain differs from the skeleton it follows.

## Module map

Every component of the original LBS is mapped onto one Python module, so nothing
gets lost in translation.

| Original | Port | Responsibility |
|---|---|---|
| `_common.asp` | `config.py` + `app.py` | configuration, data directory, bootstrap, site switch |
| `class/dbconn.asp` | `db.py` | connect, query, write, transactions, backups |
| `class/functions.asp` | `utils.py` | input handling, encoding, pagination links, dates, highlighting, width-aware length |
| `class/cache.asp` | `cache.py` + `settings.py` | settings, categories, groups, smilies, word filters, recent articles/comments, calendar, counters |
| `class/user.asp` | `users.py` + `auth.py` + `visitors.py` | users, login, registration, rights, visitor records |
| `class/article.asp` | `articles.py` | article read/write, neighbours, visibility rules |
| `class/ubbcode.asp` | `ubbcode.py` | UBB → HTML, smilies, auto-linking |
| `class/upload.asp` | `uploads.py` | upload validation and storage |
| `class/md5.asp`, `class/sha1.asp` | `hashlib` | password digests |
| `source/src_default.asp` | `articles.py` list endpoints | index filtering, pagination, view mode |
| `source/src_article.asp` | `articles.py` | `act=new/edit/save/update/delete` |
| `source/src_comment.asp` | `comments.py` | comment list plus `act=save/update/delete` |
| `source/src_gbook.asp` | `guestbook.py` | guestbook list plus `act=save/update/delete` |
| `source/src_user.asp` | `users.py` | `act=edit/update/delete` |
| `source/src_login.asp` | `auth.py` | `act=login/logout`, plus login throttling |
| `source/src_register.asp` | `auth.py` | registration |
| `source/src_trackback.asp` | `trackback.py` | list/delete and the ping receiver |
| `source/src_admin.asp` | `admin.py` | every admin section |
| `source/src_feed.asp` | `feed.py` | RSS and JS output |
| `source/src_stats.asp` | `stats.py` | visitor list |
| `scode.asp` | *not ported* | security code is disabled (decision 6) |

## API

The complete list — parameters, permissions and response shapes — lives in
`docs/api.md` and `docs/openapi.json`, both generated by `make docs` from
`server/src/openapi_spec.py`. Treat those as the source of truth; this section
only summarises.

Every public path carries a `.asp` suffix (`/api/articles.asp`,
`/api/articles/1/comments.asp`, …). `app.AspPathMiddleware` strips it before
routing, so the routes themselves stay clean.

| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/login.asp`, `POST /api/auth/logout.asp`, `GET /api/auth/me.asp`, `POST /api/auth/register.asp` |
| Articles | `GET/POST /api/articles.asp`, `GET/PATCH/DELETE /api/articles/<id>.asp` |
| Comments | `GET/POST /api/articles/<id>/comments.asp`, `GET/PATCH/DELETE /api/comments/<id>.asp` |
| Guestbook | `GET/POST /api/guestbook.asp`, `GET/PATCH/DELETE /api/guestbook/<id>.asp` |
| Trackback | `GET /api/trackbacks.asp`, `DELETE /api/trackbacks/<id>.asp`, `GET\|POST /trackback.asp` (ping) |
| Users | `GET /api/users.asp`, `GET/PATCH/DELETE /api/users/<id>.asp` |
| Site | `GET /api/site.asp`, `/api/lang.asp`, `/api/health.asp`, `/api/categories.asp`, `/api/archive.asp`, `/api/stats.asp`, `/api/stats/visitors.asp`, `/feed.asp` |
| Upload | `POST /api/upload.asp`, `GET /api/upload/limits.asp`, `GET /uploads/<name>` |
| Admin | `/api/admin/{info,settings,categories,groups,smilies,wordfilter,database,attachments,announce,links,misc,site-state,login,logout}.asp` |

## Authentication and permissions

- Flask session cookie, `HttpOnly` + `SameSite=Lax`; `SECRET_KEY` comes from
  `data/secret_key`, created as 32 random bytes with mode 0600 when missing.
- Unauthenticated requests: `/api/*` returns a 401 JSON body, page requests are
  redirected to `/login?next=…`.
- Pages and static assets are public; only the read-only APIs are reachable
  without a session. Guests may still comment and sign the guestbook, exactly
  like the original, with the handlers enforcing the guest group rights.
- The admin backend needs a second login (`POST /api/admin/login.asp`) with the
  administrator's password on top of the site session, mirroring `Session("admin")`.
- Passwords: `SHA1(password + user_salt)`; a legacy `MD5(password)` row is
  verified once and rewritten with a fresh salt and hash.
- Rights: the five `group_rights` digits become `{view, post, edit, delete,
  upload}`; `>1` applies to every object, `==1` only to the user's own.
- Article visibility: `log_mode` 1 public, 2 needs login, 3 needs `view>=2`,
  4 needs `view>=3`; hidden categories need `view>=2`.

## Deliberate differences

- The original concatenates SQL strings in JScript; this port uses parameterised
  queries throughout, with equivalent behaviour.
- The ASP `Application`-scoped cache (settings, categories, calendar, counters)
  became an in-process TTL cache backed by the database.
- Access' `Year()` / `Month()` / `Day()` became SQLite `strftime()`.
- Access' `TOP n` became `LIMIT n`.
- The security code lives in the Flask session rather than ASP `Session`, and is
  currently switched off.
- Deleting a user refuses to remove the last administrator, and deleting a
  trackback uses the same rights rule as articles (see the plan README for the
  reasoning).
